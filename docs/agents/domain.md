# Domain Docs（领域文档）

本文件规定工程类 Skills 在理解代码库时如何使用仓库的领域文档。

## 开始分析前

- 阅读仓库根目录的 **`CONTEXT.md`**。
- 阅读 **`docs/adr/`** 中与当前工作区域相关的 ADR。

任一位置不存在时直接继续。只有实际明确了领域术语或需要长期保留的架构决策时，领域建模 Skills 才按需创建这些文件。

## 文件结构

本仓库采用单一上下文：

```
/
├── CONTEXT.md
├── docs/adr/
│   └── ...
└── ApiAutomation/
```

## 使用统一领域语言

在 issue、假设、测试或重构建议中命名领域概念时，使用 `CONTEXT.md` 定义的术语，并避免使用 glossary 明确排除的同义词。

需要的概念尚未记录时，先检查仓库是否已使用其他术语。确实存在术语缺口时，将其交给 `domain-modeling` 处理，不创建平行词汇。

## 识别 ADR 冲突

拟议工作与现有 ADR 冲突时，明确指出冲突，并说明为什么可能需要重新审视原决策。
